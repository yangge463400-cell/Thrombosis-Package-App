# 医院多租户管理系统 · 设计与实现文档

> 交付日期：2026-08-14 ｜ 模块：医院端（医院管理员）+ 管理员端（平台管理员）双入口
> 核心能力：动态医院名展示、医护管理 CRUD（数据隔离）、医院管理员 CRUD、权限闭环

---

## 一、数据库表结构设计

**零新表**：复用现有 `user` 与 `hospital` 两张表，通过 `role` + `hospital_id` 实现多租户。

### 1. `user` 账号表（用户/医护/医院管理员/平台管理员 统一存储）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | 账号 ID |
| `phone` | VARCHAR(20) | **登录账号**（医护/管理员用手机号+密码登录；平台 admin 用固定账号） |
| `password` | VARCHAR(100) | **BCrypt 加密**密码（仅医护/管理员使用，C 端用户走微信登录） |
| `nickname` | VARCHAR(64) | 显示名称 |
| `role` | VARCHAR(20) | **角色标识**：`staff`=医护 / `hospital_admin`=医院管理员 / `admin`=平台管理员 / `user`=C 端用户 |
| `hospital_id` | BIGINT | **租户标识**：关联 `hospital.id`。医院管理员与医护**必须绑定**，平台 admin 为 NULL（跨租户） |
| `status` | TINYINT | 1 正常 / 0 禁用（禁用后无法登录） |
| `created_at` / `updated_at` | DATETIME | 审计字段 |

### 2. `hospital` 医院表（租户主数据）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | 医院 ID（种子数据 1~6：协和/北医三院/复旦中山/瑞金/广东省人民/南方） |
| `name` | VARCHAR | 医院名称（**前端顶部动态展示来源**） |
| `city` / `address` / `phone` / `detectTime` | - | 医院基础信息 |
| `status` | VARCHAR | cooperating=合作中 / disabled=停用 |

### 3. 多租户关键设计

```
user.hospital_id ──FK──▶ hospital.id
        │
        ├─ role='staff'           → 医护（医院端可增删改查，锁定本院）
        ├─ role='hospital_admin'  → 医院管理员（平台端创建，绑定某医院）
        └─ role='admin'           → 平台管理员（hospital_id 为 NULL，跨租户管理）
```

- **数据隔离边界**：一切查询/修改都围绕 `hospital_id` 过滤；医院管理员的操作被服务端强制锁死为本院，前端传参不可覆盖。

## 二、后端接口清单（契约）

所有接口统一响应 `{ code, message, data }`，`code==0` 成功；需要 `Authorization: Bearer <token>`。

### 2.1 登录与账号信息

| 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|
| POST | `/api/admin/login` | 公开 | 平台/医院管理员登录，**返回 `hospitalName`**（从数据库关联获取） |
| GET | `/api/admin/me` | admin, hospital_admin | 当前账号信息（含 `hospitalName`），前端刷新后恢复展示 |

**登录响应示例（医院管理员）**：
```json
{
  "code": 0,
  "data": {
    "token": "eyJ...",
    "userId": 9,
    "nickname": "中山管理员",
    "role": "hospital_admin",
    "hospitalId": 3,
    "hospitalName": "复旦大学附属中山医院"
  }
}
```

### 2.2 医护管理（医院端 / 平台端）

| 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|
| GET | `/api/admin/staffs?page&pageSize&keyword&hospitalId` | admin, hospital_admin | 医护列表。**医院管理员强制只查本院**（忽略 hospitalId 参数）；平台可按医院过滤/全量 |
| POST | `/api/admin/staffs` | admin, hospital_admin | 新增医护。医院管理员自动绑定本院；平台必须传 `hospitalId` |
| PUT | `/api/admin/staffs/{id}` | admin, hospital_admin | 编辑医护（账号/姓名/状态/可选改密码）。**医院管理员仅能改本院** |
| DELETE | `/api/admin/staffs/{id}` | admin, hospital_admin | 删除医护。**医院管理员仅能删本院** |
| POST | `/api/admin/staffs/{id}/reset-password` | admin, hospital_admin | 重置密码 |

**新增医护请求体**：
```json
{ "phone": "13811110001", "password": "123456", "nickname": "中山护士小王", "hospitalId": 3, "status": 1 }
```
> 医院管理员调此接口时**无需传 hospitalId**（传了也会被强制覆盖为本院）；编辑时 `password` 留空 = 不改密码。

### 2.3 医院管理员管理（仅平台）

| 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|
| GET | `/api/admin/hospital-admins?page&pageSize&keyword&hospitalId` | admin | 医院管理员列表 |
| POST | `/api/admin/hospital-admins` | admin | 新增医院管理员，**必须指定 `hospitalId`**（如复旦大学附属中山医院 id=3） |
| PUT | `/api/admin/hospital-admins/{id}` | admin | 编辑（可改手机号/姓名/所属医院/状态/密码） |
| DELETE | `/api/admin/hospital-admins/{id}` | admin | 删除（删除后该账号无法登录医院端） |
| POST | `/api/admin/hospital-admins/{id}/reset-password` | admin | 重置密码 |

**新增医院管理员请求体（核心示例）**：
```json
{ "phone": "13900000099", "password": "abc123456", "nickname": "中山管理员", "hospitalId": 3, "status": 1 }
```

## 三、鉴权与数据隔离逻辑（核心）

### 3.1 三层防护

```
① JWT 鉴权（AuthInterceptor）
   Authorization: Bearer <token> → 解析出 { userId, role, hospitalId } 存入 ThreadLocal
   @RequireRole({"admin"}) 等注解校验角色，不匹配 → 403

② 租户锁定（resolveHospitalId）
   hospital_admin → 强制返回 ctx.getHospitalId()，忽略前端传的 hospitalId
   admin         → 使用前端显式指定的 hospitalId（null = 全量）

③ 归属校验（assertOwnHospital）
   编辑/删除前：若为 hospital_admin，校验目标记录的 hospitalId == 当前账号 hospitalId
   否则 → 403「无权操作其他医院的账号」
```

### 3.2 关键代码（`AdminService.java`）

```java
/** 多租户数据隔离核心：计算实际生效的 hospitalId。
 *  hospital_admin 一律锁定当前账号所属医院，忽略前端传入值，杜绝越权 */
private Long resolveHospitalId(String role, Long reqHospitalId) {
    if ("hospital_admin".equals(role)) {
        Long hid = UserContext.get() == null ? null : UserContext.get().getHospitalId();
        if (hid == null) {
            throw new BusinessException(ErrorCode.FORBIDDEN, "账号未绑定医院，无法操作");
        }
        return hid; // 锁定本院
    }
    return reqHospitalId; // admin 显式指定（可为 null = 全量）
}

/** 数据隔离：医院管理员操作的目标账号必须属于当前账号的医院 */
private void assertOwnHospital(String role, User target) {
    if ("hospital_admin".equals(role)) {
        Long hid = UserContext.get() == null ? null : UserContext.get().getHospitalId();
        if (hid == null || !hid.equals(target.getHospitalId())) {
            throw new BusinessException(ErrorCode.FORBIDDEN, "无权操作其他医院的账号");
        }
    }
}
```

- 新增医护：`createStaff()` 中 `resolveHospitalId` 强制绑定本院 → **越权传 hospitalId 会被静默覆盖**（见验证记录 [7]）
- 编辑/删除：`updateStaff/deleteStaff` 先 `requireAccount` 再 `assertOwnHospital` → 跨院操作 403（见验证记录 [8]）
- 角色隔离：`/api/admin/hospital-admins` 标注 `@RequireRole({"admin"})`，医院管理员访问 → 403（见验证记录 [F]）
- 账号唯一：`checkPhoneUnique()` 新增/改号前查重（编辑排除自身），防重复登录账号
- 密码安全：统一 `BCryptPasswordEncoder` 加密存储，永不返回明文

## 四、前端实现方案

### 4.1 路由与菜单（`router/index.js` + `stores/auth.js`）

| 角色 | 新增菜单 | 路由 | 页面 |
|---|---|---|---|
| admin（平台） | 医院管理员 | `/hospital-admins` | `views/hospital-admins/index.vue` |
| hospital_admin（医院） | 医护管理 | `/staffs` | `views/staffs/index.vue` |

路由带 `roles` 守卫（`router.beforeEach` 校验角色），无权限访问 → 重定向回工作台。

### 4.2 动态医院名展示（需求 1）

- **登录时**：`adminApi.login` 返回 `hospitalName` → `auth.setLogin(data)` 存入 Pinia + localStorage；
- **刷新后**：`Layout.vue` 挂载时调用 `auth.fetchMe()` → `GET /api/admin/me` 从数据库重新拉取医院名，**不依赖本地缓存**；
- **展示位**：
  - `SideBar.vue` 顶部：`{{ auth.hospitalName }} · 管理后台`（替换原写死的"北京协和医院"）
  - `TopBar.vue` 左侧标签：`{{ auth.hospitalName }}` + "数据范围：本院"
  - `login/index.vue` 提示文案：去掉写死的"（北京协和医院）"

### 4.3 医护管理页（`views/staffs/index.vue`）

- 医院管理员：顶部显示黄色"数据范围：本院"标签，**隐藏医院下拉**，新增弹窗医院为固定显示；
- 平台管理员：显示医院下拉（可全量/按医院筛选），新增弹窗**必须选医院**；
- 表格操作：编辑 / 重置密码 / 删除（ElMessageBox 二次确认）；
- 列表字段：ID、登录账号、姓名、所属医院（`hospitalName`）、状态、创建时间。

### 4.4 医院管理员管理页（`views/hospital-admins/index.vue`）

- 仅平台可见（菜单+路由双重角色控制）；
- 新增弹窗：账号、姓名、初始密码、**所属医院下拉（如"复旦大学附属中山医院"）**、状态；
- 编辑弹窗：可改所属医院（改后该账号登录进入新医院）；
- 删除确认文案特别提示"删除后该账号将无法登录医院端"。

## 七、已知限制与后续建议

1. `user.phone` 当前为普通索引（`idx_phone`），账号唯一靠代码层查重；并发极端场景可加唯一索引（`ALTER TABLE user ADD UNIQUE KEY uk_phone (phone)`，需先清理重复数据）；
2. 删除医院管理员/医护为**硬删除**；如需审计可改为 `deleted` 标记软删；
3. 医院管理员修改所属医院后，旧 token 仍含旧 `hospitalId`（JWT 有效期 7 天）；如需立即生效可让拦截器每次校验账号当前 `hospital_id`；
4. 密码重置未做强制下次修改；可扩展 `password_reset_required` 字段。
